# AGENTS.md

Telegram-бот для магазина при санатории: принимает фото чеков, сопоставляет товары
с Excel-номенклатурой и собирает дневные Excel-отчёты с зарплатными колонками.
Проект только под Windows, без git, тестов и файла зависимостей. Python 3.11,
`openpyxl` + `Pillow`; Telegram и Gemini вызываются через `urllib` (без фреймворка).

## Сначала прочитать

- `Инструкции DeepSeek.md` — существующее техническое описание (на русском). Держать в актуальном состоянии при изменении поведения.
- `Инструкция.md` — инструкция для продавца; бот отдаёт её по кнопке `📖 Инструкции`.
- `bot_config.json` — рабочий конфиг **и секреты** (токен бота, ключ Gemini, разрешённые чаты, корень данных, модель). Не выводить и не копировать секреты в код/документацию.

## Где лежат реальные данные

- Корень данных бота — `G:\Sanator` (`root` в `bot_config.json`), **не** папка `Sanator` внутри этого проекта. Этот проект на GHO — рабочая копия/архив; правки здесь не попадут в боевую копию, пока их не перенести на SPQR.
- `Sanator\<ГГГГ>\foto\<ММ>\<ДД.ММ.ГГГГ>\data.json` — единственный источник истины. Дневные и месячные xlsx собираются из него; удалять xlsx безопасно, правки в нём не сохранятся.
- Отчёт за период (месяц) **никогда не читает дневные xlsx**: `collect_rows()` берёт `data.json` и пересчитывает все позиции по самой свежей номенклатуре (`_rows(..., fresh=True)`), поэтому старые категории не «замораживают» итог.
- Номенклатура `Sanator\<ГГГГ>\nom\<ММ>\*.xlsx` — **только чтение**. `bot_main.nom_for()` берёт файл с самой поздней датой изменения (`(2)` новее, чем без него), игнорируя `paths.nom`.
- `_CATALOG_CACHE` кэшируется по пути и времени файла, поэтому замена номенклатуры подхватывается без перезапуска; дополнительно кэш очищается при построении отчёта за период.
- `план.json` в той же папке `nom\<ММ>` хранит план месяца; команда `план <сумма>` в чате записывает его.

## Приоритет конфигов и опасные файлы

- Проценты зарплаты берутся из `проценты_категорий` в `bot_config.json`, который **перекрывает** `Конфиг.json` (`bot_sales.load_app_config` объединяет их, приоритет у `bot_config.json`). `paths.config` указывает на `G:\\Sanator\\Bot\Конфиг.json`, поэтому правка `Конфиг.json` в этом проекте обычно ни на что не влияет.
- `stavki.json` используется только в `apply_rates.py`; рабочий бот его не читает, если проценты категорий заданы.
- Даты до `01.11.2026` принудительно относятся к категории «Матрица» без вопросов (`SPLIT_DATE` в `bot_sales.py`).
- Бот сам пишет `bot_config.json` во время работы (переключение модели, доступ по коду) и `bot_state.json` (незавершённые диалоги). Не редактировать и не перезаписывать их при запущенном боте.
- Все исходники и JSON — UTF-8 с кириллическими именами и строками. Сохранять кодировку; в PowerShell использовать `-Encoding UTF8`.

## Карта кода

- `bot_main.py` — опрос Telegram, клавиатура/кнопки, сценарий вопросов, разбор дат, дневные и периодические отчёты.
- `bot_sales.py` — хранение дня, сборка Excel из 14 колонок, конфиг/ставки/план, ключи дублей.
- `sales_core.py` — загрузка номенклатуры и нечёткое сопоставление; файл номенклатуры никогда не записывает.
- `bot_vision.py` — подготовка изображений и вызовы Ollama/Gemini. `bot_vision_local.py` — однострочный шим совместимости.
- `apply_rates.py` — служебный скрипт пересчёта зарплатных колонок в готовых xlsx.
- `депо\` и `python bot_main.py\` — устаревшие снимки; править только модули в корне. `create_excel_files.py` — посторонний черновой скрипт, пишет в `D:\ADeepSeek\ПАПКА`.

## Известные ловушки

- **Не запускать `python apply_rates.py` на текущих отчётах.** Его номера колонок (6/8/9/10) устарели относительно текущей раскладки из 14 колонок (ставка = колонка 10, зарплата = 11), поэтому он затирает «Количество», «Категория», «Нал.», «Ставка». Использовать только `--demo` или пересобирать xlsx из `data.json`.
- `catalog_for()` возвращает `list` (`sales_core.load_catalog`), а ветка `select_nom` в `bot_main.py` обращается с ним как с `dict` (`items.keys()`), поэтому выбор товара из встроенного списка падает. При правке менять обе стороны.
- Проверка дублей идёт по ФД+ФН, затем по дате+времени+сумме, затем по дате+сумме (`bot_sales._keys`). Все три правила сохранять при изменении хранения чеков.
- Дата чека берётся с чека, а не по времени загрузки; путь папки строится по этой дате (включая год и месяц).
